## MODULE 0: Agentic Reasoning Frameworks
**Order:** 0
**Description:** Master the logic loops that separate static chatbots from autonomous agents.

### Concept: agent-logic-react
- **Objective:** Implement and optimize the ReAct (Reason + Act) framework for complex task solving.
- **Order:** 0

#### [NOTES] The ReAct Paradigm: Thought, Action, Observation

The ReAct framework is the foundational logic for modern AI agents. Unlike zero-shot prompting, ReAct forces the model to generate a "Thought" process before taking an "Action."
1. **Thought:** The agent explains what it needs to do and why.
2. **Action:** The agent selects a specific tool or API call.
3. **Observation:** The agent reads the output from the tool.
4. **Iteration:** The agent updates its next "Thought" based on the "Observation."

#### [MCQ] ReAct Logic Verification
- **Question:** In the ReAct framework, what is the primary purpose of the 'Thought' step before an 'Action'?
- **Options:** A) To increase the token count and billing.
    B) To allow the model to plan its approach and justify tool selection.
    C) To provide a summary for the end-user.
    D) To bypass the need for external API tools.
- **Correct:** B
- **Explanation:** The 'Thought' step is critical for planning and logical consistency, ensuring the model picks the correct tool based on context.

## MODULE 1: Multi-Agent Orchestration & Patterns
**Order:** 1
**Description:** Design systems where specialized agents collaborate to solve high-ticket business problems.

### Concept: multi-agent-patterns
- **Objective:** Identify and implement Hierarchical vs. Joint Collaboration agent patterns.
- **Order:** 0

#### [NOTES] Architecting Multi-Agent Hierarchies

When tasks become too complex for a single agent, we use Multi-Agent Systems (MAS).
1. **Hierarchical Pattern:** A "Manager" agent receives the high-level goal and delegates sub-tasks to specialized "Worker" agents.
2. **Sequential Pattern:** Agents work in a fixed order, passing the output of one as the input to the next.
3. **Joint Collaboration:** Agents operate in a shared environment and chime in based on expertise.

#### [MCQ] Pattern Selection
- **Question:** Which architecture is most suitable for a complex project requiring strict oversight and task delegation?
- **Options:**
    A) Simple Sequential Pipeline
    B) Joint Collaboration
    C) Hierarchical (Manager-Worker) Pattern
    D) Single Agent Zero-Shot
- **Correct:** C
- **Explanation:** The Hierarchical pattern allows a 'Manager' to oversee sub-tasks, ensuring quality control and structured execution.

## MODULE 2: Tool Integration & Memory Systems
**Order:** 2
**Description:** Connecting agents to the physical world and maintaining state across long-running tasks.

### Concept: agent-memory-state
- **Objective:** Manage short-term and long-term memory for stateful agent interactions.
- **Order:** 0

#### [NOTES] State Management and Long-Term Memory

An agent must remember past interactions without being overwhelmed by noise.
- **Short-term Memory:** Managed via the context window (recent conversation history).
- **Long-term Memory:** Managed via RAG (Retrieval-Augmented Generation) and Vector Databases.
When an agent encounters a problem, it queries its "Experience Vault" (Vector DB) to see how it solved similar problems previously.

#### [MCQ] Memory Optimization
- **Question:** What is the primary function of a Vector Database in an agentic system?
- **Options:**
    A) To store the agent's source code.
    B) To provide a long-term 'experience' retrieval mechanism (Long-term Memory).
    C) To replace the LLM entirely.
    D) To manage the user's login session.
- **Correct:** B
- **Explanation:** Vector Databases allow agents to perform semantic searches over past data, effectively serving as long-term memory.

## MODULE 3: Security, Guardrails & Governance
**Order:** 3
**Description:** Protecting the system from malicious prompts and managing operational costs.

### Concept: agent-security-01
- **Objective:** Implement prompt injection defenses and PII masking.
- **Order:** 0

#### [NOTES] Protecting the "Digital Realm"

Elite systems require strict guardrails to prevent "rogue" behavior.
1. **Prompt Injection Defense:** Using system-level filters to prevent users from overriding agent instructions.
2. **PII Masking:** Ensuring the agent does not send Personally Identifiable Information to third-party APIs.
3. **Budget Guardrails:** Setting hard limits on token usage per session to prevent infinite logic loops from draining capital.

#### [MCQ] Cost Governance
- **Question:** What is the most effective way to prevent a ReAct agent from incurring excessive API costs?
- **Options:**
    A) Asking the user to monitor it.
    B) Setting a 'Maximum Iterations' limit on the reasoning loop.
    C) Using a smaller font in the UI.
    D) Only using agents during business hours.
- **Correct:** B
- **Explanation:** A hard cap on iterations prevents the agent from getting stuck in a costly recursive loop.
