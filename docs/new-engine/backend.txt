3.3  diagnostic_status  (view or computed columns)
The frontend polls GET /api/diagnostic/status/:studentId. The simplest implementation is a Supabase view that queries student_competency_matrix and returns one boolean per skill. Sarthak can implement this as a Postgres view or a computed query in the route handler â€” either is acceptable.

-- Suggested Postgres view
CREATE VIEW diagnostic_status AS
SELECT
  student_id,
  bool_or(skill = 'listening' AND band_score IS NOT NULL)  AS listening_scored,
  bool_or(skill = 'reading'   AND band_score IS NOT NULL)  AS reading_scored,
  bool_or(skill = 'writing'   AND band_score IS NOT NULL)  AS writing_scored,
  bool_or(skill = 'speaking'  AND band_score IS NOT NULL)  AS speaking_scored,
  (bool_or(skill = 'listening' AND band_score IS NOT NULL)
   AND bool_or(skill = 'reading'  AND band_score IS NOT NULL)
   AND bool_or(skill = 'writing'  AND band_score IS NOT NULL)
   AND bool_or(skill = 'speaking' AND band_score IS NOT NULL))
                                                            AS overall_complete
FROM student_competency_matrix
GROUP BY student_id;

3.4  Level derivation logic
Every time a band_score is written to student_competency_matrix, the level column must be computed and stored. Apply this logic in the Matrix Writer before the upsert â€” do not leave level calculation to the frontend.

function deriveLevel(bandScore) {
  if (bandScore &gt;= 7.0) return 'C';
  if (bandScore &gt;= 5.0) return 'B';
  return 'A';
}

6.  Matrix Writer â€” upsert logic
Every scoring pipeline ends with a call to the Matrix Writer. This is a shared utility function Backend writes once and calls from all four scoring routes. It must be idempotent â€” calling it twice with the same student_id and skill must not create duplicate rows.

// Pseudocode for Matrix Writer
async function writeToMatrix({ student_id, skill, band_score, sub_scores }) {
  const level = deriveLevel(band_score);

  // Upsert: insert or update based on (student_id, skill) unique constraint
  const { error } = await supabase
    .from('student_competency_matrix')
    .upsert({
      student_id,
      skill,
      band_score,
      level,
      sub_scores: sub_scores || null,
      last_updated: new Date().toISOString()
    }, {
      onConflict: 'student_id,skill',
      // Increment assessments_count using Postgres function, not client-side
      ignoreDuplicates: false
    });

  // Increment assessments_count via RPC to avoid race conditions
  await supabase.rpc('increment_assessments_count', { p_student_id: student_id, p_skill: skill });

  if (error) throw new Error('Matrix write failed: ' + error.message);
}

// Supabase RPC function to create:
CREATE OR REPLACE FUNCTION increment_assessments_count(p_student_id uuid, p_skill text)
RETURNS void AS $$
  UPDATE student_competency_matrix
  SET assessments_count = assessments_count + 1
  WHERE student_id = p_student_id AND skill = p_skill;
$$ LANGUAGE sql;


7.  Recommendation seed trigger
After all four skills are scored, the backend must fire a webhook to n8n. n8n will then run the recommendation rule engine and insert the first 3â€“5 suggestion rows for the student. This is what populates the student's Suggestions tab when they first reach the dashboard.

Backend implements this trigger by checking, after each Matrix Writer call, whether all four skills are now scored for that student. If yes, fire the webhook exactly once. Use a flag column on the students table to prevent double-firing.

// After every Matrix Writer call, check if diagnostic is complete
async function checkAndTriggerRecommendationSeed(student_id) {
  const { data } = await supabase
    .from('diagnostic_status')   // the view from Section 3.3
    .select('overall_complete, recommendation_seeded')
    .eq('student_id', student_id)
    .single();

  if (data.overall_complete &amp;&amp; !data.recommendation_seeded) {
    // Fire n8n webhook
    await fetch(process.env.N8N_RECOMMENDATION_SEED_WEBHOOK_URL, {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify({ student_id })
    });

    // Mark as seeded to prevent double-firing
    await supabase
      .from('students')
      .update({ recommendation_seeded: true })
      .eq('id', student_id);
  }
}
