Onboarding
The student’s first experience. Collects: full name, target IELTS band score, target exam date, and self-assessed current level (never appeared for IELTS / appeared once / appeared multiple times). If enrolled via an institute, an institute code or email invite auto-links them to their batch and tutor. This data populates the students table and creates their initial row in student_competency_matrix with null band scores — waiting for the Diagnostic to fill them. The student can’t skip this; it’s the minimum viable profile.
Diagnostic Test
The front gate. This is not optional. A new student cannot access the Dashboard until they complete it. Composition: 6 Listening MCQ questions from a short audio clip (3 minutes), 4 Reading True/False/Not Given questions from a 200-word passage (2 minutes), and one Writing paragraph task (write 2–3 sentences explaining a given graph — not a full essay, scored on a simplified rubric). Speaking diagnostic runs after, separately — a 90-second prompted response to a simple Part 1 question, recorded and scored. Total time cap: 10 minutes. Output: a band score per skill (0.5 band precision), and an A/B/C level assignment. This writes the first four entries to student_competency_matrix and unlocks the Dashboard.
My Learning Dashboard
The central hub. Contains: four skill band score cards (current band, last change, number of assessments taken), a Level badge (A/B/C) with a “next unlock” progress bar, a “Focus Area” card which is the top recommendation from the engine (e.g., “Your Coherence sub-score in Writing is your weakest point — 3 tasks suggested”), a weekly study streak counter, and a predicted exam readiness date (calculated from current band trajectory vs. target band vs. target date). From here the student navigates to any practice module or the Insights section. Content outside their assigned level is visible but locked with a tooltip explaining how to unlock it.
Listening Module
Two modes: Practice (untimed, single question types for drills) and Mock Test (full 40-question, 30-minute timed assessment). Question types: Multiple Choice, Short Answer, Sentence Completion, Table/Form Completion, Map/Diagram Labelling — all sourced from your question bank. Audio plays once (mock mode) or can be replayed (practice mode). Submission triggers rule-based scoring: raw score out of 40 mapped to IELTS band via the official conversion table. Band score writes to student_competency_matrix with skill = 'listening'.
Reading Module
Same two-mode structure as Listening. Question types: True/False/Not Given, Yes/No/Not Given, MCQ, Matching Headings, Matching Features, Sentence Completion, Summary Completion. Three passages per mock test (Academic) or two shorter passages (General Training track — you should support both). Timed at 60 minutes for mock. Rule-based scoring — no AI needed here. Raw score / 40 → band. Writes to student_competency_matrix with skill = 'reading'.
Writing Module
Separate Task 1 and Task 2 modes, each with a prompt. The student types into a word-counted textarea (Task 1 minimum 150 words, Task 2 minimum 250 words). Submission sends the text to Claude API with the structured IELTS examiner system prompt returning four scores: Task Achievement/Response, Coherence & Cohesion, Lexical Resource, Grammatical Range & Accuracy — each as a 0–9 band with one sentence of feedback. The screen shows these four scores with band indicators and the feedback text. The overall Writing band is the mean of the four, rounded to the nearest 0.5. The sub_scores JSON column in student_competency_matrix stores all four criterion scores, not just the overall.
 Speaking Module
Three-part structure mirroring the real IELTS exam. Part 1: 3 introduction questions (30 seconds each). Part 2: 1 cue card with 1 minute preparation, 2 minutes speaking. Part 3: 2–3 discussion questions (up to 2 minutes each). The student sees the prompt, taps record, speaks, and taps stop. Each recording uploads to the backend where Whisper transcribes it. The full transcript (all parts combined) is passed to Claude API with the Speaking scoring prompt, returning four criterion scores: Fluency & Coherence, Lexical Resource, Grammatical Range & Accuracy, Pronunciation. The transcript is displayed on-screen so the student can see exactly what was transcribed. Band scores and feedback render below. This is the highest-priority screen to get working end-to-end.
Speed Reading (Beta)
Accessible from the Dashboard as a distinct feature card, not part of the main practice module navigation. The student sees a passage (typically 300–500 words), clicks Start, reads, and clicks Done — recording elapsed time. They then answer 5 comprehension questions. Score displayed as: Words Per Minute (WPM) + Comprehension Accuracy %. This data feeds a separate speed_reading_sessions table. It does not yet write to the main competency matrix — connection to the recommendation engine is a Phase 2 item. The beta badge is intentional; students understand it’s early-stage. This is Gokul’s feature to wire once the core pipeline is stable.
Assessment History
A reverse-chronological list of all assessments the student has completed. Each row shows: skill, date, band score, mode (practice vs. mock). Filter bar: skill type, date range, mode. Tapping any row opens the full feedback for that session — the four criterion scores, the AI feedback text, and the transcript (for Speaking). This is the student’s paper trail and is critical for showing progress over time. It reads directly from assessment_history with student filter.
Suggestions (Targeted Learning)
Populated entirely by the recommendation engine. Each card shows: resource title, resource type (video/article/exercise), the specific weakness it targets (e.g., “Coherence & Cohesion — Writing”), estimated time to complete, and a “Mark complete” button. Resources link to external YouTube videos or blog posts based on tags in the content_library table. At the top, a callout message like: “Your Fluency sub-score in Speaking is 5.5 — complete these 3 resources before your next assessment.” This screen should never be empty after the Diagnostic; it always has at least 3 suggestions. The quality of this screen is the product’s long-term moat — invest heavily in tagging the content library correctly.
Reports
Three views accessible via tabs: Band Arc (line chart of band score over time per skill, all four on one chart), Competency Radar (radar/spider chart showing current band per skill with target band overlay), and Predicted Readiness (current trajectory vs. target band vs. exam date, with a simple “at current pace” estimate). The predicted readiness calculation is: (target band − current band) ÷ average band improvement per assessment × estimated sessions per week. This doesn’t need ML — it’s arithmetic. Below the charts, a performance table shows each assessment in rows. Gokul owns the chart implementation; Recharts or Chart.js on the frontend handles the visualizations.
Profile & Settings
Name, profile photo, target exam date (editable, updates the readiness calculation), target band score (editable), exam type (Academic/General Training toggle), notification preferences (email/push, frequency), and linked institute/batch info (read-only if enrolled via institute). Password and email change flows. This screen is the last to build — implement it after core functionality is stable.
